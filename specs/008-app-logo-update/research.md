# Research: App Logo Update

**Feature**: `specs/008-app-logo-update` | **Date**: 2026-09-24

All unknowns resolved by direct inspection of the repo and source artwork. No open NEEDS CLARIFICATION.

## R-01: Source artwork properties (measured, not assumed)

- **Decision**: Treat all three files as 1254×1254px, fully **opaque white** background artwork (verified with .NET `System.Drawing`: corner pixels A=255, near-white on all three files).
  - `logo-only.png` (~738KB): black "C"-hanger mark + brown wardrobe, no wordmark.
  - `logo-full.png` (~926KB): same mark + black `CLOSY` wordmark underneath.
  - `logo-text.png` (~521KB): reserved, not shipped unless a surface needs the wordmark alone.
- **Rationale**: 1254px is more than enough for every target (largest: iOS 1024, Android xxxhdpi 192px). Opaque-white is ideal for iOS (App Store forbids alpha in the 1024 icon) and blends seamlessly onto the login background `#FAFAFA`.
- **Consequence**: No transparency to preserve; never place the raw black mark directly on the charcoal primary (`#111111`) — always keep its white tile (launcher foreground, adaptive icon) or a light backdrop.
- **Alternatives considered**: Requesting transparent re-exports from design — rejected, unnecessary for the in-scope surfaces.

## R-02: Android launcher approach

- **Decision**: Replace the legacy `mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher.png` files (48/72/96/144/192px, generated by downscaling `logo-only.png` with padding so the mark respects the ~66% diameter safe zone) **and** add an adaptive icon `mipmap-anydpi-v26/ic_launcher.xml` + `ic_launcher_round.xml` with charcoal (`#111111`, `@color/ic_launcher_background`) background and the white-tiled mark as foreground. Manifest (`android:icon="@mipmap/ic_launcher"`) stays unchanged.
- **Rationale**: `minSdk = flutter.minSdkVersion` (< 26), so legacy PNGs are still required for older devices; adaptive icon gives correct masking on API 26+. Keeping the white tile as foreground on charcoal matches the agreed "primary background" direction and keeps the black mark legible.
- **Alternatives considered**: Adding the `flutter_launcher_icons` dev-dependency — rejected, a one-shot manual placement is auditable and adds no dependency. Adaptive-only without legacy PNGs — rejected, breaks pre-26 devices.

## R-03: iOS app icon approach

- **Decision**: Replace all image files listed in `ios/Runner/Assets.xcassets/AppIcon.appiconset/Contents.json` (20pt→1024px slots, 16 files) with downscales of `logo-only.png` (with padding, opaque — already compliant with the no-alpha 1024 rule). `Contents.json` itself is unchanged.
- **Rationale**: Standard asset-catalog replacement; opaque artwork means zero alpha violations. Physical-device verification agreed in clarify (Mac/Xcode available).
- **Alternatives considered**: None — this is the only supported mechanism.

## R-04: In-app login header approach

- **Decision**: In `lib/features/auth/presentation/login_screen.dart`, delete the 68×68 rounded `Container` + `Icons.checkroom_rounded` placeholder and render `Image.asset('assets/images/logo-full.png', ...)` directly (aspect-preserving fit, display width ~200–240 logical px). Ship a resized copy (max dimension ~512px, ~100–200KB) under a new `assets/images/` bundle declared in `pubspec.yaml`. Original 1254px files stay untouched outside the repo.
- **Rationale**: Matches clarify (full lockup, no frame). App UI is light-only (no `ThemeMode`/`darkTheme` in `lib/`; scaffold bg `AppColors.background #FAFAFA`), so the opaque-white artwork blends with no extra treatment — the "verify visually" step in FR-006 is a check, not extra work.
- **Alternatives considered**: Wrapping in a white card — rejected, contradicts the agreed frameless direction and is unnecessary on `#FAFAFA`.

## R-05: App-size budget (SC-004: ≤ +5MB)

- **Decision**: Ship only resized/compressed outputs (Android mipmaps ≈ tens of KB, iOS set ≈ ~1MB worst case, in-app copy ≈ ~150KB). Total expected addition well under 1MB.
- **Rationale**: Measured source total is ~2.2MB; nothing ships at full 1254px except pixels actually needed (1024 iOS slot).
- **Alternatives considered**: Shipping originals as Flutter assets — rejected, wasteful and risks the size budget for zero visual gain.
