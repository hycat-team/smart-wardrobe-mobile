## 2. Fix: `serverClientId` không có fallback trên Android

### 2.1 Vì sao

`google_sign_in_android` 7.x chạy qua **Credential Manager**, bắt buộc có
`serverClientId`. Nguồn `getCredential()`:

```java
String serverClientId = params.getServerClientId();
if (serverClientId == null || serverClientId.isEmpty()) {
  → GetCredentialFailureType.MISSING_SERVER_CLIENT_ID
}
```

Phía Dart (`google_sign_in_android.dart:init`):
`_serverClientId = params.serverClientId ?? await _hostApi.getGoogleServicesJsonServerClientId();`
— nhánh fallback đọc resource Android `default_web_client_id`.

Repo **chưa có** resource đó (không có `google-services.json`, không có
`res/values/strings.xml`). Nghĩa là: build release mà quên
`--dart-define=GOOGLE_CLIENT_ID` → `AppConstants.googleClientId` = `''` →
`GoogleSignInBootstrap.ensureInitialized` bỏ qua `initialize()` →
`MISSING_SERVER_CLIENT_ID`. Triệu chứng **tệ nhất**: nút đứng loading vĩnh viễn,
không báo lỗi, không log (`authenticate()` await thẳng `getCredentialAsync`, không
timeout sẵn — code đã tự thêm timeout 2 phút ở `google_sign_in_button.dart:112`).

### 2.2 Đã làm

Thêm `android/app/src/main/res/values/strings.xml` với
`default_web_client_id` = Web client ID production. Đây là **fallback**, app vẫn
ưu tiên `serverClientId` truyền từ Dart như trước. Xác minh đã vào APK:

```
aapt2 dump resources app-arm64-v8a-release.apk
  resource 0x7f0f003a string/default_web_client_id
    () "368645245473-5ovjq88e58p97u81asjssbt2bt8bnpt9.apps.googleusercontent.com"
```

Lần build đầu **fail** vì comment trong XML chứa `--` (Android resource parser
cấm `--` trong comment):
`strings.xml:9:11: Error: The string "--" is not permitted within comments.`
→ viết lại comment bằng chữ thường không dấu gạch, build pass.

### 5.1 Bẫy thật đã gặp: make **lặng lẽ** fallback sang `cmd.exe`

make trên Windows mặc định gán `SHELL = sh.exe`, nhưng `sh.exe` **không có trên
PATH**. make **không báo lỗi** — nó âm thầm dùng `cmd.exe`, nên:

- `echo "x"` → in ra `"x"` (kèm dấu nháy, vì `cmd /c echo` giữ nguyên quotes)
- `if [ -f f ]` → lỗi cú pháp
- mọi recipe nhiều dòng hỏng

Ba lần thử để sửa, ghi lại vì rất dễ lặp lại:

1. `SHELL := sh.exe` → **fail**, chính là lỗi trên.
2. `SHELL := C:/Program Files/Git/usr/bin/sh.exe` → `CreateProcess(NULL, …)`.
   Đường dẫn có **khoảng trắng**, make tách sai argv.
3. `$(wildcard "C:/Program Files/Git/usr/bin/sh.exe")` → rỗng. GNU Make build
   for Windows cần dấu `*` để glob, và **không escape khoảng trắng** trong
   `wildcard`.
4. `$(wildcard C:/Program\ Files*/Git/usr/bin/sh.exe)` → sai nữa: `firstword`
   cắt tại khoảng trắng, ra `C:/Program`.
5. **Đúng**: `GIT_SH := $(wildcard C:/Program*/Git/usr/bin/sh.exe)` rồi
   `SHELL := "$(GIT_SH)"` — giữ **dấu nháy kép** để argv đúng.

Cũng bỏ `.RECIPEPREFIX` dùng TAB, chuyển sang `>`: TAB trong Makefile dễ bị
`missing separator` khi editor làm mất khoảng trắng hay copy-paste.

Recipe viết **an toàn cho cả `sh` lẫn `cmd.exe`** (không dấu nháy, không
ký tự chuyển hướng `> < | &`) để máy không cài Git for Windows vẫn chạy được.
